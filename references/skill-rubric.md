# Skill Quality Rubric

Skill 质量评估的评分标准，每个维度 0-5 分制，带具体锚点。

## 维度 1：触发准确性（Trigger Accuracy）

| 分 | 描述 | 典型问题 |
|----|------|---------|
| 5 | trigger_words 精准匹配目标场景，无误触，边界清晰 | — |
| 4 | 基本准确，有 1-2 个边缘 case 需要优化 | 缺少变体词 |
| 3 | 覆盖主要场景，但有明显的误触或漏触 | "帮我" 过于宽泛 |
| 2 | 触发词过于宽泛或过于狭窄 | 几乎所有 query 都触发 |
| 1 | 触发词几乎无法正确匹配目标场景 | 关键词拼写错误 |
| 0 | 没有 trigger_words 或完全失效 | — |

## 维度 2：描述清晰度（Description Clarity）

| 分 | 描述 | 典型问题 |
|----|------|---------|
| 5 | 一句话能说清 skill 是做什么的，≤50 字，措辞精准 | — |
| 4 | 基本清晰，50-100 字，有 1-2 处可优化 | 包含过多实现细节 |
| 3 | 能看懂，但 100-200 字或表述冗长 | "当用户想要...的时候" |
| 2 | 描述模糊，>200 字，需要读完全文才能理解 | 废话多 |
| 1 | 描述与实际功能不符 | 夸大功能 |
| 0 | 没有 description 或完全误导 | — |

### 评分规则

| 字数 | 分数调整 |
|------|----------|
| ≤ 50 字 | +5 |
| 51-100 字 | +4 |
| 101-200 字 | +3 |
| > 200 字 | +2 |
| 有逗号连接的复合句 | -0.5 |
| 有"等"字出现 | -0.5 |

## 维度 3：结构完整性（Structure Completeness）

检查项（每项 1 分，最高 6 分）：

| 检查项 | 说明 |
|--------|------|
| 有 name 字段 | frontmatter 中的 name |
| 有 description 字段 | frontmatter 中的 description |
| 有前置条件说明 | 如何启用 skill，是否需要上下文 |
| 有边界情况处理 | 不适用场景、"红线"等 |
| 有示例 | 至少 1 个实际使用示例 |
| 有相关 skill 引用 | 与其他 skill 的关系 |

**评分映射：** (得分/6) × 5，保留 1 位小数

---

## 维度 4：指令可操作性（Actionability）

| 分 | 描述 | 典型问题 |
|----|------|---------|
| 5 | 每条指令都是可执行的动作，无歧义 | — |
| 4 | 基本可操作，有 1-2 处需要澄清 | "适当的时候" |
| 3 | 主要指令可执行，部分模糊 | "确保一致" |
| 2 | 大量模糊表述，需要大量推断 | "考虑周全" |
| 1 | 指令之间矛盾或自相否定 | 前后矛盾 |
| 0 | 没有可执行的指令 | — |

### 模糊词汇检测

| 词汇 | 分值影响 |
|------|----------|
| "适当" / "适时" / "必要时" | -0.5 |
| "确保" / "保证" / "必须" | +0.5 |
| "考虑" / "建议" / "可以" | -0.3 |

**注意：** 自相矛盾的段落直接 1 分

---

## 维度 5：真实效果（Practical Effect）

这个维度需要实际运行 skill 才能评估：
- 用预设的 test cases 跑 skill
- 评判输出是否符合预期
- 标记"说得好但做得差"的情况

**注意：** 这个维度只在深度模式下评估

---

## 综合评分计算

```
综合分 = (触发准确性 × 0.2) + (描述清晰度 × 0.2) + (结构完整性 × 0.2) + (指令可操作性 × 0.25) + (真实效果 × 0.15)
```

权重说明：
- 指令可操作性权重最高（0.25）：skill 的核心价值在于可执行
- 真实效果权重最低（0.15）：需要额外工作，且"说得好但做得差"会被指令可操作性捕获

```markdown
| 触发准确性 | 4.5 | ✓ 良好 |
| 描述清晰度 | 3.0 | ⚠ 需改进 |
| 结构完整性 | 4.0 | ✓ 良好 |
| 指令可操作性 | 3.5 | ⚠ 需改进 |
| 真实效果 | — | ⏸ 需手动验证 |

## 结构扫描结果
- [✓] 有 name 字段
- [✓] 有 description 字段
- [ ] 缺少示例章节
- [✓] 有边界情况说明

## Top 5 问题（按严重程度）

1. **[高]** description 过于冗长（247 字），建议精简至 50 字以内
2. **[中]** 缺少"不适用场景"说明，用户可能误用
3. **[中]** 某些指令措辞模糊（如"适当的时候"），需要明确定义

## 改进建议

### 必须修复
- [ ] 精简 description 至 50 字以内
- [ ] 添加"不适用场景"章节

### 建议优化
- [ ] 增加 1-2 个实际示例
```
