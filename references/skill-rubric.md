# Skill Quality Rubric

评分锚点细则。**公式、权重、层模型的唯一真源是 SKILL.md（失效分层模型 + Step 4）——本文件只放各层锚点，不另立公式、不复制报告模板；两者冲突时以 SKILL.md 为准并回改本文件**（本文件曾自带旧五维公式与"真实效果权重最低 0.15"，与七层表打架数个版本无人发现——failure-log #2 同型，十三评修复）。

> **版本与 pin**：本文件改动一个字都要重算历史深度报告的可比性。以文件内容 hash 前 8 位为版本，随深度报告的配置段一起 pin：
> `shasum -a 256 references/skill-rubric.md | cut -c1-8`（家规：references/rubric-design.md 第 5 条）

## 评分体系（本文件不复制权重表）

公式、定档权重、前置检查清单的唯一真源是 **SKILL.md Step 4**（v6：前置检查不进分；深度综合分按高档 0.25 ×2 = 方法论/执行、中档 0.15 ×2 = 触发质量/可操作性、0.10 ×2 = 身份/口径复算；证据纪律层 v6 起为报告合格门、不进被测分）。本文件只放各层锚点，此处不照抄数字——**照抄过一次就漂移过两次**。改权重只改 SKILL.md Step 4，并重算本文件 hash 写进深度报告配置段。

## 锚点细则

### 触发层（静态部分＝引擎维度一，v6 按环境分流）

**LLM 路由环境**（无 `_meta.json`/trigger_words——Claude/ZCode/Codex 标准形态）：本维不适用（引擎返回 None），触发质量由 description 触发覆盖度承担（见写作质量层①）。**关键词路由环境**（有 trigger_words）按下方锚点：

| 分 | 描述 | 典型问题 |
|----|------|---------|
| 5 | trigger_words 精准匹配目标场景，无误触，边界清晰 | — |
| 4 | 基本准确，有 1-2 个边缘 case 需要优化 | 缺少变体词 |
| 3 | 覆盖主要场景，但有明显的误触或漏触 | "帮我" 过于宽泛 |
| 2 | 触发词过于宽泛或过于狭窄 | 几乎所有 query 都触发 |
| 1 | 触发词几乎无法正确匹配目标场景 | 关键词拼写错误 |
| 不适用 | 无 trigger_words（LLM 路由环境） | 看 description 覆盖度 |

数量与问题词判定以引擎 `score_trigger_accuracy` 为准（1-10 合理、11-15 偏多、>15 过多；"帮我/试试/test/help/make/do/请"为问题词）。深度模式以 `test_triggers.py` 实测修正。

### 写作质量层

**description 触发覆盖度（维度二，v6 判据）**——覆盖度以引擎 `score_description_coverage` 为准，长度不进判据：

| 分 | 描述 |
|----|------|
| 5 | 做什么 + 何时用（Use when/你说/当用户/提到…）+ 负边界（不触发/不适用…） |
| 4 | 做什么 + 何时用，缺负边界 |
| 3 | 做什么 + 负边界，缺何时用 |
| 2 | 只有做什么，无触发语境（高优先级——LLM 路由下最可能漏触发） |
| ≤2 | 过短说不清做什么，或 >1024 字符（违反开放标准） |
| 0 | 无 description |

（旧"≤50 字满分/>200 字 2 分"判据已废——官方范例 docx/pdf/xlsx 的 description 为 437-948 字符，全球 693 个 skill 中位 357，长 description 正是官方要求的写法。failure-log #13。）

**结构参考项（维度三）**——六项各 1 分，(n/6)×5：name / description / 边界 / 示例 / **常见坑(gotchas)** / 相关。v6 起：缺项只出低优先级建议（参考项不判缺项扣档）；正文级"前置条件/何时使用"小节不计入（触发判据在 description，正文在触发后才加载）；词表以引擎 `_has_boundary` 等四个谓词为单一来源。

**指令可操作性（维度四，v6 按类型分档）**——锚点：

| 分 | 工具型 | 咨询型 |
|----|--------|--------|
| 5 | 可执行锚点 + 验证闭环 + 解释 why 齐备，无对冲词 | 结构锚点（分支表/决策树）+ 示例 + 解释 why 齐备 |
| 4 | 缺一项加分锚点 | 缺一项加分锚点 |
| 3 | 基线：无锚点也无矛盾 | 基线 |
| ≤2.5 | 指令矛盾（禁令与许可同段共词） | 同左 |

引擎机械段：工具型 +1.0 命令/代码块、+0.5 验证闭环、+0.5 解释 why，对冲词（适当/适时/酌情/视情况）每个 −0.3；咨询型 +1.0 结构锚点、+0.5 示例、+0.5 解释 why；混合型两档均值。旧"必须/禁止 +0.2/+0.3、考虑/建议/可以扣分"的词频已废（官方指引：满篇刚性指令是黄旗；咨询型启发式措辞合法）。深度报告人工段照旧：判"能否被整段跳过"，两段取较低档、人工不得高于引擎。

### 身份层

一致 = 5；存疑 = 3；矛盾 = 1（引用两处原文）。判据见 SKILL.md 身份层。

### 口径层

通过 = 5；存疑 = 3；失效 = 1。机械项（元数据同步/版本对齐）引擎代查，数字复算（权重和=1、徽章=引擎实测）评审者做。

**两路结论并存时取较低档**（机械 ✓ ＋ 人工复算存疑 → 本层 3），层清检表按两段式写：`✓ 通过（机械项）｜人工 ⚠ 存疑：…`（failure-log #10）。

### 承诺层

通过 = 5；部分缺失 = 3；幽灵文件 = 1。存在性引擎代查；深度追加真源内容审计＋依赖健康度（failure-log #9）。

### 方法论层

5 每步有主且就地可发现 / 4 有主但需翻找 / 3 主不存在（承诺层同扣）/ 2 无主步骤（真断链）/ 未审计不得给分。委派有效原则与跨工件术语一致性见 SKILL.md 方法论层。

### 执行层

5 全部实跑通过且退出码契约吻合（含价值增量对比：带/不带 skill 有可观察差异）/ 4 能跑但边界行为与文档不符 / 2 有命令跑不起来或零价值增量 / 未实跑不得给分。完备性检验（好样本全过、坏样本全挂）为 gate 型不可跳过项（failure-log #9）。

### 证据纪律层（v6 起为报告合格门，不进被测分）

分档表见 SKILL.md 证据纪律层；机械核由 `scripts/check_report.py <report.md> --skill <path>` 出（锚数字 / 层结论 / 证据块 / 深度综合分逐行复算四项，rc 0 全过 / 1 有不符 / 2 参数或文件错）。机械核报红＝**报告作废重做**（不是扣被测 skill 的分——仪表误差不进考生分数）；未跑机械核不得出深度综合分。
