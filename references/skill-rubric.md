# Skill Quality Rubric

评分锚点细则。**公式、权重、层模型的唯一真源是 SKILL.md（失效分层模型 + Step 4）——本文件只放各层锚点，不另立公式、不复制报告模板；两者冲突时以 SKILL.md 为准并回改本文件**（本文件曾自带旧五维公式与"真实效果权重最低 0.15"，与七层表打架数个版本无人发现——failure-log #2 同型，十三评修复）。

> **版本与 pin**：本文件改动一个字都要重算历史深度报告的可比性。以文件内容 hash 前 8 位为版本，随深度报告的配置段一起 pin：
> `shasum -a 256 references/skill-rubric.md | cut -c1-8`（家规：references/rubric-design.md 第 5 条）

## 评分体系（照抄 SKILL.md Step 4，此处仅索引）

- **静态四维分（快速模式，引擎输出）**：触发 × 0.25 + 描述 × 0.25 + 结构 × 0.25 + 可操作性 × 0.25——只覆盖触发层（静态）与写作质量层；身份/口径/承诺以层清检表呈现，不进数字
- **深度综合分（七层加权）**：触发 0.15 / 写作质量 0.15 / 身份 0.10 / 口径 0.10 / 承诺 0.10 / 方法论 0.20 / 执行 0.20——方法论与执行最高：评价一个 skill 的核心，是它承诺的东西真的能发生

## 锚点细则

### 触发层（静态部分＝引擎维度一）

| 分 | 描述 | 典型问题 |
|----|------|---------|
| 5 | trigger_words 精准匹配目标场景，无误触，边界清晰 | — |
| 4 | 基本准确，有 1-2 个边缘 case 需要优化 | 缺少变体词 |
| 3 | 覆盖主要场景，但有明显的误触或漏触 | "帮我" 过于宽泛 |
| 2 | 触发词过于宽泛或过于狭窄 | 几乎所有 query 都触发 |
| 1 | 触发词几乎无法正确匹配目标场景 | 关键词拼写错误 |
| 0 | 没有 trigger_words 或完全失效 | — |

数量与问题词判定以引擎 `score_trigger_accuracy` 为准（1-10 合理、11-15 偏多、>15 过多；"帮我/试试/test/help/make/do/请"为问题词）。深度模式以 `test_triggers.py` 实测修正（见 SKILL.md 触发层）。

### 写作质量层

**描述清晰度（维度二）**——字数与扣分以引擎 `score_description_clarity` 为准：

| 分 | 描述 |
|----|------|
| 5 | 一句话说清 skill 做什么，≤50 字，措辞精准 |
| 4 | 基本清晰，51-100 字 |
| 3 | 能看懂，101-200 字或表述冗长 |
| 2 | 模糊，>200 字，需读完全文才能理解 |
| 1 | 描述与实际功能不符 |
| 0 | 无 description |

扣分：含"当用户…的时候" −0.3；含"等" −0.5；逗号连接复合句 >3 −0.5。

**结构完整性（维度三）**——六项各 1 分，(n/6)×5：name / description / 前置条件 / 边界情况 / 示例 / 相关 skill。

**指令可操作性（维度四）**——锚点：

| 分 | 描述 | 典型问题 |
|----|------|---------|
| 5 | 每条指令都是可执行的动作，无歧义 | — |
| 4 | 基本可操作，有 1-2 处需澄清 | "适当的时候" |
| 3 | 主要指令可执行，部分模糊 | "确保一致" |
| 2 | 大量模糊表述，需要大量推断 | "考虑周全" |
| 1 | 指令矛盾或自相否定 | 前后矛盾 |

词表以引擎为单一来源：模糊词 −0.5（适当/适时/必要时/酌情/视情况）、−0.3（考虑/建议/可以/或许）；加分词 +0.2（必须/执行/运行/调用）、+0.3（禁止/不得/绝不）。**"确保/保证"不是加分词**（旧版误标 +0.5，十三评纠正）。自相矛盾直接 ≤2。

### 身份层

一致 = 5；存疑 = 3；矛盾 = 1（引用两处原文）。判据见 SKILL.md 身份层。

### 口径层

通过 = 5；存疑 = 3；失效 = 1。机械项（元数据同步/版本对齐）引擎代查，数字复算（权重和=1、徽章=引擎实测）评审者做。

### 承诺层

通过 = 5；部分缺失 = 3；幽灵文件 = 1。存在性引擎代查；深度追加真源内容审计＋依赖健康度（failure-log #9）。

### 方法论层

5 每步有主且就地可发现 / 4 有主但需翻找 / 3 主不存在（承诺层同扣）/ 2 无主步骤（真断链）/ 未审计不得给分。委派有效原则与跨工件术语一致性见 SKILL.md 方法论层。

### 执行层

5 全部实跑通过且退出码契约吻合 / 4 能跑但边界行为与文档不符 / 2 有命令跑不起来 / 未实跑不得给分。完备性检验（好样本全过、坏样本全挂）为 gate 型不可跳过项（failure-log #9）。
