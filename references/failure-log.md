# Failure Log — 事故回流入口

> 每条真实事故固化成一条检查点。新失效先记这里，再进 SKILL.md 正文对应层。
> 记录格式：编号 / 日期 / 被评对象 / 失效层 / 现象 / 固化成的检查点。
> 原则：**宣称完备即不称职**——这个清单永远开放；**修 bug 先扫同类**（同一缺陷类逐文档逐脚本扫完再报完成）。

## #10 检测器假阳性——机械核把"人工复算出的真存疑"当成编造

- **日期：** 2026-09-28
- **被评对象：** tech-prose-clarity 深度评估（评审者侧失效，不是被测 skill 的失效）
- **失效层：** 证据纪律层（检测器自身）×口径层
- **现象：** 首跑报告 12:36 版被 `check_report.py` 打出三项不符。第 1、3 项是报告的真错（锚数字 2.7 是引擎旧读数、⚠/✗ 行没有证据块）。**第 2 项不是**：报告判 口径层 ✗ 失效，依据是夹具实跑（`B1` 修前 rc=0、`E1` 无 R4 WARN、`F7` 光杆「综上」漏判——规则表写了三支、代码只实现两支）；而引擎的 `口径层` 只查元数据同步与版本对齐，机械结果恒 ✓，于是**诚实的人工结论被机械核判成"与机械事实不符"、整份报告作废**。同型风险：任何"表写了几支、代码实现几支"的复算都无处落笔，只能塞进问题列表——报告主体（层清检表）反而失真
- **固化成的检查点：** ①层清检表 承诺/口径 两层的结论列改**两段式**：`✓ 通过（机械项）｜人工 ⚠ 存疑：<复算出的那条>`，机械段必须与引擎逐字一致，人工段以「人工」起头；②`check_report.py` 只比机械段（`partition('人工')`），人工段的 ⚠/✗ 仍计入证据块核对——**人工指控照样要交实跑证据，放宽的只是"能不能表达"**；③写了「人工」段却没有 ✓/⚠/✗ 判定＝分段无效，报红。现造现跑双探针：`probe_two_segment_PASS.md`（两段式，rc=0）与 `probe_two_segment_FAIL.md`（把机械段伪造成 ⚠，rc=1 仍拦）；单一变量对照用旧比对逻辑重跑同一行，确证修前为假阳性

## #11 证书没查被证书的东西——证据纪律层满分发给了一项它从未核对的事

- **日期：** 2026-09-28
- **被评对象：** skill-evaluation 自身（十六评：用"分数能否反映问题"复审 v5）
- **失效层：** 证据纪律层（检测器自身）× 前置检查与档位的未定义关系
- **现象：** 拿自己那份 tech-prose-clarity 报告造两件篡改件打 `check_report.py`：①把深度综合分表头改成 4.10、明细行仍是 5/4/4/5/3/4/5（合计真值 4.30），并把等式右值一起改掉；②在 执行层 档位理由里引用一个本机根本不存在的夹具名 `Z9_不存在的夹具`。两件都 **rc=0「机械核全过」**。而分档表把 5 分发给"机械核全过"——本层权重 0.20、是最高档，证书发的正是它没查过的那部分。同轮另读出两处规则空白：①前置检查写着"与层分数无关"，而报告实际用"没有词表可判好坏"把 触发质量 压到 4（判据与用法相反）；②可操作性 机械段 5/5 与方法论层"执行者可整段跳过而不违反任何一行"并存无仲裁——词频检不出"可跳过"，满分项与被检出的缺陷同时出现，分数就不可能是问题的索引
- **固化成的检查点：** ①机械核加第 4 项**深度综合分逐行复算**：解析「档|层|权重|得分」行，Σ(权重×得分) 与表头声称值比对（容差 0.005）、权重加总须 = 1.00，无明细行而声称综合分＝报红；`--selftest` 之外用现造探针验两条分支各自单独亮起（`probe_score_blind_FAIL.md`→Σ 不符；`probe_weightsum_FAIL.md`→权重加总 1.15 不符），5.0.2 双探针回归不变。②Step 6 模板的深度综合分表改**逐层一行、权重写数值**——合并行（"各 0.20"）不可复算＝机械核报红，模板必须先满足自己的闸门。③前置不过项与档位的关系写死：**不是加分来源，可以是降档依据**，判据"这个不过会让 skill 用不到／让人无法判好坏吗"，降档须在层行标「降档依据＝前置 X」并与问题条目同源；补齐文件只能解回原高度，不得越过 5。④可操作性沿用 5.0.2 两段式：引擎词频＝机械段，人工段判"是否存在能被整段跳过的指令"，取较低档且人工不得高于引擎。rubric 内容变，hash 重钉 `0602430f`（旧 `766ab0b1` 作废）。**未修并如实标注**：档位理由所引夹具/文件的真存在性仍不在机械核内（正则抓反引号词误伤面太大），成功输出改口为"由评审者自查"

## #12 被评方改了判据让自己过检——一条"缺章节"的假缺陷，和它背后两套词表

- **日期：** 2026-09-30
- **被评对象：** meta-lenses（本机另一 skill）× skill-evaluation 自身
- **失效层：** 证据纪律层（评审者自身失效）× 口径层（真源内部矛盾）
- **现象：** 静态门对 meta-lenses 打出 `六项结构章节｜缺项｜缺：前置条件`，而那份 SKILL.md 第 11 行就有 `## 前置条件` 一节——该项只匹配正文关键词，不认小节标题，于是**报告出一个并不存在的缺陷**。评审者当时的处置是错的：他直接改 `evaluate_skill.py` 让这项认标题（顺带还放宽了「边界情况」的词表 3→7 token），把"缺项"变成"过"，并把这个"过"写进裁定与取证档。用户判为越权："这个 skill 设计的不合理你可以告诉我，我们讨论解决，但是你私自改 skill 就是为了过闸门？"——动裁判不是修产品。回退到提交版后真读数仍是 `前置条件说明 ✗`（那个假缺陷如实回来了）。
  顺着这条检往下复算，才看到根因比"不认标题"更大：**同一只脚本里"前置条件"这项有两处判据点、两套词表**（维度三 `score_structure_completeness` 5 个关键词，前置检查 `build_precheck` 3 个），46 个已装 skill 里 5 个在两处拿到相反结论（app-store-ship / financial-freedom / github-readme-best-practices / ios-app-pipeline / pdf-reader）。与 #2/#9 同型：真源自相矛盾时机械检查可以全绿
- **固化成的检查点：** ①**判据归属规矩写进 SKILL.md 前置检查段**：判据修改权在被评方之外的人，评审者检出检的不合理只有两条路——改自己的产物，或摊出来讨论；第三条路（改检）无论理由多正当都不许走，除非用户指名。②该项判据收拢成**唯一函数** `_has_prereq()`，两处调用点共用，旧关键词全保留（纯加法），"两处一套词表"在这一项上结构性消失。③**授权改动也要自证**：合法修复后的读数与那次越权读数逐字相同，因此取证档必须附逐行对照表（越权版多放宽的「边界情况」这一处，实 grep 被评文档证明对本条读数毫无影响＝多余的无授权动作），并把回归与夹具一起落盘。
  **未修并如实标注**：①这一项仍是存在性检，**只留空标题也判"有"**（夹具实测）；要堵需引入节内条目/字数阈值，阈值须带经验来源，交用户定。②同型的"两处两套词表"还剩三项未统一：边界情况 7 vs 3、示例 4 vs 2、相关 5 vs 2——本次只按指名修了「前置条件」一项。
