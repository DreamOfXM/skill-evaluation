# Failure Log — 事故回流入口

> 每条真实事故固化成一条检查点。新失效先记这里，再进 SKILL.md 正文对应层。
> 记录格式：编号 / 日期 / 被评对象 / 失效层 / 现象 / 固化成的检查点。
> 原则：**宣称完备即不称职**——这个清单永远开放；**修 bug 先扫同类**（同一缺陷类逐文档逐脚本扫完再报完成）。

- **失效层：** 证据层（评估者自身）

## #9 外部调研漏检——声明之外的四类盲区

- **日期：** 2026-09-26
- **被评对象：** ui-design-router（声明→实测评测 vs 外部生态调研的产出差集）
- **失效层：** 评估范围层（检查生成规则）
- **现象：** 声明→实测评测 31 项全绿，外部调研却挖出四条真问题：①finesse-ui 与 beauty_gate 两套"寄存器"同名不同义（组成性问题，单工件验证照不到）；②BEAUTY_RUBRIC B1 判据 ≥16px 与自家真值"两站 14px"矛盾（真源只查了存在性）；③impeccable 双版本号＋零更新跟踪（无依赖健康维度）；④finesse-ui 0.20.0 本体能力与 router 挂载面不匹配（需生态知识才能提出问题）
- **固化成的检查点：** 声明→实测只回答"它说的是不是真的"；深度模式追加四项——承诺层真源内容审计与依赖健康度、方法论层跨工件术语一致性（路由/委派型必查）、执行层完备性检验（v1.5.0 概念在 4.0.0 重写中丢失，本条回归并升为 gate 型不可跳过）。归因口诀：评测能发现什么由问题定义决定
