# LLM-as-Judge 与 Rubric 设计

judge 是测量仪器，不是真理。它有已知系统性偏差：偏爱长回答、偏爱同族模型的风格、受答案顺序影响。以下是把它校准到可用的完整流程。

## 什么时候才用 judge

判定阶梯（SKILL.md 第 3 节）里 judge 排最后。先穷尽前两档：

- 可执行验证（跑测试 / 编译 / 脚本断言）
- 结构化抽取比对（输出 JSON 比字段）

只有"开放性质量"（翻译好不好、总结得全不全、回复得体不得体）才需要 judge。

## Rubric 怎么写

**逐维度、带锚点**。禁止"1–10 分打整体印象"——那种分数不可复现，也无法定位问题。

每个维度给 0/1/2（或 0–3）档的**具体行为描述**，锚点写到"照着能机械对号"的程度。示例（评"客服 agent 回复质量"）：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 事实一致 | 陈述与所给资料矛盾，或编造政策/数字 | 全部陈述可由资料支持 | 同 1，且主动指出资料未覆盖处、不臆测 |
| 行动有效 | 没有给可执行步骤 | 给了步骤但缺关键信息 | 步骤完整、顺序正确、无多余步骤 |
| 边界遵守 | 承诺了资料外的补偿/时限 | 无越权但语气含糊 | 在权限内明确作答，越界问题正确转人工 |

及格线写死在 rubric 里（例：所有维度 ≥1 且总分 ≥4）。

## Judge prompt 骨架

```
你是评分员。只依据下面给出的【资料】判定【回复】，逐维度打分。
先引用回复中支撑你判断的原句，再给分。资料未覆盖、无法判定 → 该维度记 0 并注明"无法判定"，不要猜。

【评分表】<rubric 原文贴入>
【题目】…
【资料】…
【回复】…

输出 JSON：
{"dims": {"事实一致": {"quote": "...", "score": 2, "reason": "..."}, ...},
 "pass": true}
```

要点：

- judge 温度设 0。
- 要求**先引用证据再打分**——显著抑制臆测打分。
- 允许输出"无法判定"而不是硬打；无法判定的比例进报告（>10% 说明 rubric 或资料有问题）。

## 校准（每次换 rubric 或换 judge 模型都要重做）

1. 人标 20–30 题。这是唯一不能省的人工投入，你自己标。
2. judge 盲打同样这批题。
3. 算 **Cohen's kappa**（排除随机一致），并同时分别报「过」「挂」两类的一致率：

   ```python
   def kappa(a, b):
       """a, b：两个人（人与 judge）对同一批题的 0/1 判定列表"""
       n = len(a)
       po = sum(x == y for x, y in zip(a, b)) / n          # 观察一致率
       pa, pb = sum(a) / n, sum(b) / n                     # 各自判"过"的比例
       pe = pa * pb + (1 - pa) * (1 - pb)                  # 随机一致期望
       if pe == 1:  # 同质批次（人标全过/全挂）：kappa 数学上无定义
           return 1.0 if po == 1 else 0.0
       return (po - pe) / (1 - pe)
   ```

   （同源实现：`scripts/_common.py` 的 `kappa()`，改判据时两边同步——或直接 import。上两轮验证中"过线/被拒"方向曾两次写反，单一副本消灭各自写反的机会。）

4. **kappa ≥ 0.6 才准上线（≥ 0.8 更稳）**。不用原始一致率的原因：90% 样本都是「过」时，无脑全判「过」的 judge 原始一致率高达 90%，kappa 却是 **0.00**——judge 的边缘分布是 1.0，随机一致期望 pe = 0.9×1.0 + 0.1×0.0 = 0.9，恰好等于观察一致率；恒判一类的评分器 kappa 必为 0，即零信息。类不平衡会骗过原始一致率。人标全过/全挂的同质批次会走守卫分支返回 1.0——那只是不让工具崩，这种校准集本身没有鉴别力（无脑 judge 也满分），必须补难例/边界例重新人标，1.0 不是通行证。**阈值自身也有抽样误差，且数字有成立条件**（MC 2 万次）：均衡边际（过挂约 50/50）下 n=25 时真 kappa 0.5 约 26–28% 过线、真 0.8 约 8% 被误拒；人标偏斜到 90% 判过时恶化到约 35%/15%；加题收效缓慢——n=40 漏检仍约 23%，压到 ≤10% 需要 130+ 题。所以 kappa 是**初筛不是硬闸门**：要么把校准做到 130+ 题，要么接受初筛误差、绝不单凭 0.6 附近一档之差做 go/no-go；上线后的 5% 复评才是真闸门。不够就修锚点（通常是写得太抽象，加具体例子），改完重测。
5. rubric 改动一个字，重新校准。所以 rubric 要有版本号：以文件内容 hash 前 8 位为版本（`shasum -a 256 rubrics/x.md | cut -c1-8`），随报告配置段一起 pin。

## 已知偏差与对策

| 偏差 | 对策 |
|---|---|
| 自我偏好（judge 偏爱同族模型） | judge 与被测模型用不同家族 |
| 位置偏差（A/B 对比偏爱第一个） | 每对样本正反各评一次，两次结论不一致记平局 |
| 冗长偏好 | rubric 显式加"多余信息扣分"维度 |
| 随时间漂移 | 温度 0 + 固定 judge 版本 + 抽 5% 复评查自一致 |

## 泄漏

judge prompt 里只放判定所需的资料，**不放被测系统的 prompt**——否则 judge 会"理解"出题意图而放水。
