# 触发词测试方法

当需要进行深度评估时，触发词测试是重要的环节。

## 为什么需要测试触发词

触发词是 skill 被调用的入口。如果触发词设置不当：
- **过宽**：任何请求都触发，导致误触
- **过窄**：只有特定说法才能触发，导致漏触
- **缺失**：根本没有触发机制

## 测试方法

### 1. 构建测试集

测试集应包含三类 query：

| 类型 | 数量 | 示例 |
|------|------|------|
| **正例**（应该触发） | 5-10 | "帮我头脑风暴" |
| **负例**（不应该触发） | 5-10 | "帮我写代码" |
| **边界**（可能触发也可能不触发） | 3-5 | "brainstorming" |

### 2. 执行测试

```bash
python3 ~/.agents/skills/skill-evaluation/scripts/test_triggers.py <skill-path>
```

或者手工测试：

```python
def should_trigger(query, trigger_words):
    """判断 query 是否应该触发 skill"""
    query_lower = query.lower()
    for tw in trigger_words:
        tw_lower = tw.lower()
        if tw_lower in query_lower:
            return True
    return False
```

### 3. 分析结果

| 指标 | 计算方式 | 理想值 |
|------|---------|--------|
| 命中率 | 正例中触发数 / 正例总数 | ≥ 80% |
| 漏触率 | 正例中未触发数 / 正例总数 | ≤ 20% |
| 误触率 | 负例中触发数 / 负例总数 | ≤ 10% |

### 4. 优化建议

**命中率低（漏触多）：**
- 添加同义词（如 "头脑风暴" → "头脑风暴", "brainstorm", "创意发散"）
- 添加变体（如 "帮我" → "帮我", "请帮我", "我想"）
- 添加英文对应词

**误触率高（误触多）：**
- 移除过于通用的词（如 "帮我", "test", "help"）
- 增加限定词（如 "头脑风暴" 而不是 "风暴"）
- 移除长度 ≤ 2 的词

## 触发词设计原则

1. **精准优先**：宁可漏触，不要误触
2. **数量适中**：5-15 个为宜
3. **长短搭配**：有核心词，也有变体
4. **定期维护**：随着使用反馈调整

## 示例：brainstorming skill 的触发词设计

```json
{
  "trigger_words": [
    "头脑风暴",
    "brainstorm",
    "帮我头脑",
    "想做头脑",
    "创意发散",
    "设计方案讨论"
  ]
}
```

**分析：**
- ✓ 包含中英文
- ✓ 包含"帮我"变体
- ✓ 不包含过于通用的"帮我"
- ✓ 长度适中
