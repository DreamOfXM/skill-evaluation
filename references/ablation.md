# 组件消融（Ablation）：找出承重指令

skill/prompt 的每一段都是成本——token、注意力稀释、维护负担——但不是每一段都在干活。消融回答的问题是：**删掉这段，分数掉不掉**。不掉，就删。

## 流程

复用现有 harness：同一批评测用例（回归集够用）、同判定器、同 n，对比工具直接用 `scripts/compare_runs.py`。

1. 跑完整版，得到基线（n ≥ 3）。
2. 构造处理组：**一次只删一段**（单变量）。"一段"可以是 SKILL.md 的一节、一条红线、few-shot 的一个示例。
3. 处理组跑同一批用例。
4. `compare_runs.py` 对比，判读见下。
5. 删掉所有不承重的段后，重跑一次回归集——确认组合删除没有意外交互。

## 判读

| 结果 | 结论 |
|---|---|
| 分数显著下降 | 承重，保留 |
| 噪声内不掉 | 测不出作用。注意 ≠ 无用：题量低于最小可检差异（`references/statistics.md`）时小作用检不出，删之前先确认题量够 |
| 分数上升 | 这段在帮倒忙（常见于过度约束或互相矛盾的指令），删，并记下教训 |

## 两个坑

- **交互冗余**：两段说同一件事，删任何一段分数都不掉——逐段删会漏检。怀疑时做成对删除验证。
- **对评测集过拟合**：如果评测题就是照着某段指令的措辞出的，消融会高估该段作用。消融结论只在评测集分布内有效。

## 边界：消融查得出冗余，查不出缺失

消融是减法：输入只能是**已写下的**段落，"根本没写"的维度删无可删，分数永远不掉、看起来一切正常。"14 段全承重"只担保这 14 段，不担保没有该有的第 15 段。查缺失用**完备性检验**（SKILL.md 第 2 节）：拿已知正确答案的真实案例去撞判据，是加法。一减一加，配对才完整。

## 为什么值得做

短 prompt 不是妥协，是收益：留下的每条指令权重更高，注意力不被无效内容稀释。有公开案例（2026-09 引入时未存档原始链接，引用前需自行复核）：约 85 token 的 6 行 skill 版本对比约 552 token 完整版，82 条工作流实测输出 token 约省 8.5%、无可检出质量下降；但同一来源提醒——省的只是可见输出，总账单未必降，上下文窗口和工具定义才是大头。指令数量与效果不是单调正相关的——**没被消融验证过的指令，都只是假设；被验证过的也只是"写下的都有用"，不等于"该写的都写了"**。
